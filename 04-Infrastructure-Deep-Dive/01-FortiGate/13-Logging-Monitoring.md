# 📖 Purpose

Logging is one of the most critical functions of the FortiGate firewall. Every connection, authentication attempt, security event, configuration change, and system activity can be recorded to provide complete visibility into the enterprise network.

A properly designed logging architecture enables administrators to monitor traffic, investigate incidents, troubleshoot problems, meet compliance requirements, and perform forensic analysis after security events.

---

# 🎯 Design Objectives

- Monitor Network Activity
- Record Security Events
- Audit Administrative Changes
- Support Troubleshooting
- Enable Incident Response
- Meet Compliance Requirements
- Centralize Log Collection
- Improve Security Visibility

# 📌 What is Logging?

Logging is the process of recording events generated by the FortiGate firewall during normal operation.

These events provide visibility into:

- Network Traffic
- Security Incidents
- VPN Connections
- User Authentication
- Configuration Changes
- System Health
- Administrative Activity

---

# 🌍 Why Logging is Important

Logging helps administrators to:

- Detect Security Threats
- Investigate Attacks
- Troubleshoot Connectivity Issues
- Monitor Firewall Health
- Verify Policy Enforcement
- Generate Audit Reports
- Meet Regulatory Compliance

Without logging, administrators have limited visibility into firewall activity.

---

# 📊 Log Categories

FortiGate records different types of logs depending on system activity.

| Log Type | Description |
|----------|-------------|
| Traffic Logs | Allowed and denied network sessions |
| Event Logs | System and administrative events |
| Security Logs | IPS, Antivirus, Web Filter, Application Control |
| VPN Logs | SSL VPN and IPSec VPN events |
| Authentication Logs | User and administrator logins |
| System Logs | Device status and hardware events |
| Configuration Logs | Configuration changes and revisions |

# 🖥 Local Logging

FortiGate can store logs locally on:

- Internal Storage
- SSD (Supported Models)
- Memory (Temporary)

Local logging is suitable for:

- Small Deployments
- Temporary Storage
- Basic Troubleshooting

Limitations include limited storage capacity and retention.

---

# 📡 FortiAnalyzer Integration

In enterprise environments, logs are typically forwarded to **FortiAnalyzer**.

Benefits include:

- Centralized Log Storage
- Long-Term Retention
- Advanced Reporting
- Security Analytics
- Threat Correlation
- Dashboard Visualization

---

# 🌐 Syslog Integration

FortiGate supports forwarding logs to external Syslog servers.

Common Syslog platforms include:

- Syslog-ng
- rsyslog
- Graylog
- Splunk
- QRadar
- Microsoft Sentinel

This enables integration with enterprise SIEM solutions.

---

# 🔐 Security Event Logging

Security profiles generate dedicated logs.

Examples include:

- IPS Detection
- Malware Detection
- Web Filtering
- Application Control
- DNS Filtering
- Botnet Detection
- Intrusion Attempts

These logs help identify malicious activity.

---

# 👤 Administrative Logging

Every administrative activity should be recorded.

Typical events include:

- Administrator Login
- Logout
- Configuration Changes
- Firmware Upgrade
- Backup Creation
- Policy Modification
- User Creation

Administrative logs provide accountability and support auditing.

---

# 🌐 Traffic Logging

Traffic logs record details of every network session.

Typical information includes:

- Source IP
- Destination IP
- Service
- Port
- Policy ID
- Action (Allow/Deny)
- Interface
- Bytes Sent/Received
- Session Duration

These logs are essential for troubleshooting and traffic analysis.

---

# 📁 Log Retention

Log retention depends on:

- Storage Capacity
- Compliance Requirements
- Business Policy
- SIEM Integration

Enterprise environments commonly retain logs for:

- 90 Days
- 180 Days
- 1 Year
- 3 Years (Compliance)

# ⚙ Design Considerations

Before implementing logging, consider:

- Log Storage Capacity
- Retention Policy
- SIEM Integration
- Compliance Requirements
- Alerting Strategy
- Network Bandwidth
- High Availability
- Backup of Critical Logs

---

# ✅ Best Practices

- Enable logging on all critical firewall policies.
- Forward logs to FortiAnalyzer or a SIEM platform.
- Synchronize time using NTP for accurate timestamps.
- Enable administrator activity logging.
- Monitor VPN login events.
- Review security logs daily.
- Protect log servers from unauthorized access.
- Define log retention according to compliance requirements.

# 📌 Summary

Logging provides complete visibility into FortiGate operations by recording network traffic, security events, administrator activities, authentication attempts, and system events. A centralized logging architecture using FortiAnalyzer or a SIEM platform enables effective monitoring, auditing, troubleshooting, and incident response.

Proper logging is a fundamental requirement for maintaining security, operational awareness, and regulatory compliance within enterprise environments.
